# «Корочки.есть» — эталонный проект к ДЭ

Полноценное веб-приложение для портала онлайн-курсов. Сделано по образцу
**КОД 09.02.07-3-2026** (квалификация «Разработчик веб и мультимедийных
приложений», профильный уровень) и закрывает все три модуля экзамена.

Стек: **Python + Flask + SQLite + Jinja2 + HTML/CSS/JavaScript**.
Внешние CDN не используются — проект работает офлайн.

## Что реализовано

### Модуль 1 — информационные системы (25 баллов)

- Регистрация: **никнейм, пароль и повтор пароля**. Валидация на клиенте
  **и** на сервере; никнейм уникален, пароли должны совпадать.
- Пароль хранится только как хеш Werkzeug; email/телефон в учебной форме
  не запрашиваются.
  > В КОД 2026 на экзамене нужны ещё ФИО, телефон и email. Это упрощение
  > только для учебной лаборатории.
- Вход/выход, сессии, сообщения об ошибках.
- Роли «пользователь/администратор», защита `/admin` и POST-действий.
- Заявки: выбор курса, дата `ДД.ММ.ГГГГ`, способ оплаты.
- Статусы: «Новая» → «Идет обучение» → «Обучение завершено».
  «Отменена» — дополнительная функция (в КОД 2026 не требуется).
- Отзыв доступен только после завершения курса и только один раз.
- Защита от SQL-инъекций (параметры `?`), XSS (autoescape Jinja2),
  CSRF (токен в каждой POST-форме).

### Модуль 2 — дизайн (25 баллов)

- Единая дизайн-система: палитра, типографика, отступы, компоненты.
- Адаптив mobile-first, проверен на **390×844**.
- Анимации появления карточек, hover-состояния, `prefers-reduced-motion`.
- Публичный лендинг, каталог и слайдер убраны: это внутренний портал.
  Требование КОД 2026 по слайдеру остаётся в теории курса.
- Доступность: skip-link, alt, aria-атрибуты, focus-visible, контраст.

### Модуль 3 — разработка и оптимизация (25 баллов)

- Полный стек: фронтенд + бэкенд + БД.
- Личный кабинет, админ-панель, фильтр, поиск, сортировка, пагинация.
- Смена статусов; отмена с причиной — дополнительно.
- Индексы БД, отсутствие N+1, `LIMIT/OFFSET`, lazy-load изображений.
- JSON API (вариативная часть): `/api/applications`,
  `/api/admin/applications`.

## Структура

```
lab_web/
  app.py              маршруты, фильтры, обработчики ошибок
  db.py               подключение к SQLite, инициализация
  models.py           dataclass-модели и репозитории (ООП)
  security.py         валидация, CSRF, пароли, декораторы
  seed.py             демо-данные
  schema.sql          DDL: 6 таблиц, ограничения, индексы
  requirements.txt
  run.sh / run.bat
  templates/          Jinja2-шаблоны
  static/
    css/style.css     дизайн-система и адаптив
    js/app.js         меню и валидация
    img/              логотип и изображения курсов
  tests/test_app.py   smoke-тесты
```

### Маршруты

| Метод | URL | Назначение |
|---|---|---|
| GET | `/` | редирект: вход или личный кабинет |
| GET/POST | `/register` | регистрация |
| GET/POST | `/login` | вход |
| POST | `/logout` | выход |
| GET | `/dashboard` | заявки пользователя |
| GET/POST | `/applications/new` | новая заявка |
| POST | `/applications/<id>/review` | отзыв после завершения |
| GET | `/admin` | админ-панель, фильтр, поиск, пагинация |
| POST | `/admin/applications/<id>/status` | смена статуса |
| GET | `/api/applications` | JSON API пользователя |
| GET | `/api/admin/applications` | JSON API администратора |

## База данных

6 таблиц в 3НФ:

```
roles 1──M users 1──M applications M──1 courses
                     │
                     ├──1 reviews
                     └──M application_statuses
```

- `users.login` — UNIQUE, `users.email` — UNIQUE;
- `applications.payment_method` — CHECK (`cash`, `phone_transfer`);
- `reviews.rating` — CHECK 1..5;
- `reviews.application_id` — UNIQUE (один отзыв на заявку);
- внешние ключи с `ON DELETE CASCADE/RESTRICT`.

Сбросить базу:

```bash
rm instance/korochki.db
python app.py
```

Или вручную:

```bash
python seed.py instance/korochki.db
```

## Что менять под свой вариант задания

1. Предметную область и названия таблиц — в `schema.sql`, `seed.py`,
   `models.py`.
2. Поля формы и правила — в `security.py`.
3. Тексты и бренд — в `templates/` и `static/css/style.css`.
4. Статусы и сценарии — в `security.py` (`STATUSES`) и `admin.html`.

Структура «пользователь → заявка → статус → отзыв» подходит для большинства
вариантов ДЭ: курсы, клининг, аренда, ремонт, доставка, запись к врачу.
