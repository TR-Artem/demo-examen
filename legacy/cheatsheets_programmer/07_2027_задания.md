# Пять заданий ДЭ-2027 (проект КИМ 09.02.07-2-2027, ПУ)

Источник: «Образец задания для ДЭ в рамках ПУ» + Приложение 1 «Описание
предметной области». Перед экзаменом сверь с финальным КОД.

---

## Задание 1. Разработка базы данных средствами СУБД — 15 баллов, 50 мин

Компания «Чудо Обувь» продаёт обувь. Нужна система, где клиент выбирает
и заказывает одну или несколько моделей из каталога.

Функциональные требования:

- в каталоге хранится актуальное количество **товарных позиций** —
  сочетаний модели и размера;
- у каждой модели есть изображение;
- клиент выбирает одну или несколько пар нужного размера и модели;
- в интерфейсе — список заказов: дата, ФИО клиента;
- управление заказами.

Что сделать:

1. БД в **3НФ**, ссылочная целостность, согласованные имена, PK/FK,
   ограничения FK, отражающие предметную область.
2. **ER-диаграмма в PDF**: таблицы, связи, атрибуты, ключи.
3. Подготовить файлы с пометкой `import` и загрузить данные.
4. Сохранить **скрипт БД с данными** (или `.dt` для 1С).

Вход в систему — **только по логину** из списка пользователей, пароль не нужен.
Пользователи: администратор, менеджер, авторизованный, неавторизованный.

## Задание 2. Разработка алгоритма и создание приложения — 10 баллов, 40 мин

- алгоритм работы системы оформления заказа (Приложение 1);
- **алгоритм расчёта цены с учётом скидки**;
- алгоритмы реализовать кодом;
- название приложения включает название компании;
- единый стиль по Приложению 3: цвета, шрифты, логотип, иконка, заголовки окон;
- код: CamelCase (C#/Java), snake_case (Python), стандарт ИТС (1С);
  **не более одной команды в строке**.

Каталог:

- изображение (или `picture.png`), категория, наименование, производство,
  состав, цена со скидкой;
- количество: **«много», если суммарно больше 5 пар, иначе «мало»**;
- **светло-красная подсветка**, если суммарный остаток ≤ 3;
- **скидка 25%** товарам, по которым **не было заказов в предыдущем
  календарном месяце** (относительно даты расчёта).

Отладка: приложение работает без аварийных завершений.

## Задание 3. Интерфейс и оформление заказа — 25 баллов, 60 мин

- вход **только по логину**; после входа — ФИО в правом верхнем углу;
- последовательный интерфейс, «Назад», заголовок каждого окна;
- обработка исключений: сообщения с заголовком и пиктограммой, полезный текст,
  порядок действий; валидация текстовых полей;
- комментарии только в неочевидных местах;
- сортировка по цене ↑↓ через выпадающий список;
- фильтр по категории, первый пункт **«Все категории»** (сбрасывает фильтр);
- поиск по **наименованию и описанию**;
- поиск, сортировка и фильтрация — **в реальном времени**, совместно,
  сортировка сохраняется;
- карточка товара: изображение, производство, наименование, категория,
  цена со скидкой, состав, описание, размерный ряд, доступные размеры;
- выбрать размер и количество → добавить позиции → подтвердить заказ →
  сохраняется дата; можно отказаться на любом этапе;
- после заказа — обновить каталог и **пересчитать остатки**.

## Задание 4. Заказы у Администратора и Менеджера — 25 баллов, 60 мин

- список заказов: дата, ФИО клиента;
- добавлять новые позиции и удалять существующие;
- при добавлении — выбор товара из каталога **с поиском по наименованию**,
  затем карточка с выбором размера и количества;
- состав заказа: товарная позиция (наименование + производство, размер),
  количество, цена за единицу, итоговая сумма;
- **Администратор**: изменение даты заказа, удаление позиций;
- после изменений — обновить список;
- всё в **git-репозиторий**; создать **README.md** с описанием функциональности.

Практические результаты: исходный код (структурой файлов, не архив),
исполняемые файлы, файл скрипта БД, `.dt` для 1С, прочие файлы.

## Задание 5. Статистика и руководство пользователя — 25 баллов, 30 мин

Окно «Статистика заказов»:

- кнопка «Статистика» у **Менеджера и Администратора**;
- таблица всех заказов: номер, дата, ФИО клиента, итоговая сумма;
- 3 показателя: **количество заказов**, **общая выручка**,
  **средняя (или максимальная) стоимость заказа**.

Руководство пользователя:

- `Руководство_пользователя.docx` или `.pdf`, **1–2 страницы**;
- назначение программы и порядок входа;
- основные возможности + **не менее 3 скриншотов** (каталог, заказы, статистика).

Сохранение: обновлённый код, скрипт БД (или `.dt`), руководство — в git.
