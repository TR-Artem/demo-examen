# Руководство пользователя и README для сдачи (Задания 4–5)

## 1. Руководство_пользователя.docx — шаблон на 1–2 страницы

Требование КИМ: 1–2 страницы, назначение, вход, основные возможности,
**не менее 3 скриншотов**.

### Титул

```
РУКОВОДСТВО ПОЛЬЗОВАТЕЛЯ
Система оформления заказов обуви «Чудо Обувь»
Версия 1.0
```

### 1. Назначение программы

2–3 предложения: система позволяет клиентам просматривать каталог обуви,
выбирать модель и размер, оформлять заказы; менеджер и администратор
просматривают заказы и статистику.

### 2. Вход в систему

Введите логин из списка пользователей (пароль не требуется).
Для просмотра каталога без входа нажмите «Без входа».
После входа ФИО отображается в правом верхнем углу.
**[Скриншот 1: окно входа]**

### 3. Каталог и оформление заказа

Поиск по наименованию и описанию, фильтр по категории («Все категории»),
сортировка по цене. Товары без заказов в прошлом месяце — со скидкой 25%.
Строки с остатком ≤ 3 подсвечены.
Выберите товар → размер → количество → «Добавить в корзину» → «Оформить заказ».
**[Скриншот 2: каталог + карточка/корзина]**

### 4. Работа с заказами (Менеджер, Администратор)

Раздел «Заказы»: список с датой и ФИО клиента, состав заказа, добавление
и удаление позиций. Администратор может изменить дату заказа и удалить позицию.
**[Скриншот 3: заказы/состав]**

### 5. Статистика

Кнопка «Статистика»: таблица всех заказов и три показателя — количество
заказов, выручка, средний чек.
**[Скриншот 4: статистика]**

### 6. Завершение работы

Кнопка «Выход» возвращает на экран входа.

## 2. README.md для репозитория

```markdown
# Чудо Обувь — система оформления заказов

## Назначение
Учебный проект по КИМ 09.02.07-2-2027: каталог обуви, заказы, статистика.

## Стек
Python 3.10+, tkinter, SQLite.

## Запуск
python example_app.py
python example_app.py --reset   # пересоздать БД

## Аккаунты
admin / manager / asidorova (пароль не требуется), гость — «Без входа».

## Функциональность
- каталог с поиском, фильтром по категории и сортировкой по цене;
- скидка 25% товарам без заказов в прошлом месяце;
- «много/мало» и подсветка остатка ≤ 3;
- корзина и оформление заказа;
- заказы и состав заказа для менеджера/администратора;
- статистика: количество, выручка, средний чек.

## Структура
schema.sql           — скрипт БД (8 таблиц, данные)
example_app.py       — приложение
import_csv.py        — импорт CSV
data/                — файлы import
docs/                — ER.pdf, flowchart.pdf, Руководство_пользователя.docx
```

## 3. Git: минимальный набор

```bash
git init
git add .
git commit -m "Задание 1: схема БД и ER"
git remote add origin <URL-репозитория>
git push -u origin main

# дальше после каждого задания
git add .
git commit -m "Задание 3: авторизация, фильтры, заказ"
git push
```

Проверь на сайте репозитория, что файлы реально загрузились: исходники —
**папками**, не архивом; `schema.sql`, `README.md`, `ER.pdf`, `flowchart.pdf`,
`Руководство_пользователя.docx` — в корне или в `docs/`.

## 4. Скриншоты

Windows: `Win + Shift + S` — выделить область → вставить в Word (`Ctrl + V`).
На каждом скриншоте должно быть видно **работающую программу с данными**,
а не пустую форму. Минимум:

1. каталог с фильтрами/скидкой/подсветкой;
2. карточка товара или корзина;
3. список заказов или состав заказа;
4. статистика.

## 5. Частые причины потерять баллы

- руководство — 1 скриншот или скриншоты не своей программы;
- нет раздела «Вход в систему»;
- в репозитории архив вместо папки с исходниками;
- нет `README.md`;
- статистика без трёх показателей;
- кнопка «Статистика» видна гостю/пользователю.
